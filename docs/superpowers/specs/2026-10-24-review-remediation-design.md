# ECL 审核问题修复范围与设计

## 任务来源与目标

用户要求修复针对 `main @ 228efa3` 的审核报告，包括六项严重问题、重要问题、次要问题及文档不一致。报告中的构建结果是历史证据，不视为本次验证结果。本文件是执行前的范围整理，不表示已经修复。

目标：保护用户文件、允许损坏账户文件下启动界面、使异步任务失败可重试、使校验与修复遵循一致的信任边界，并以回归测试和新执行的构建证明行为。

## 约束

- Java 21、现有 Gradle 多模块结构；不引入新第三方依赖。
- 不读取真实账户数据，不联网登录，不启动用户实例，不提交或推送代码。
- 损坏账户库仍由底层拒绝写入；仅在界面读取边界降级，显示本地化提示。不能为避免崩溃把损坏内容变为空库后覆盖。
- 受管理路径先执行纯词法校验，拒绝绝对路径、反斜杠别名、`..` 段、空路径，再规范化取首段；文件系统层独立拒绝重解析点。检查不得依赖启动器当前工作目录。
- 存档、日志、截图、用户服务器列表、共享资源及 `.ecl` 不能因为整合包清单别名进入托管回退范围。
- 线程池关闭、同步拒绝、异步失败、取消、过期回调都必须释放忙状态、临时目录及锁；旧回调不得释放新任务状态。
- 三语文案一起维护；core 覆盖率下限行 60%、分支 40%，GUI 行 20%、分支 15%。
- 每项核验后再改，不为满足报告而修改本来正确的行为。

## 修复分组

### A. 账户与凭据

1. 首页读坏账户库时可启动、可见提示、账户列表降级；文件字节不变且新增/迁移仍拒绝覆盖。
2. `CachedSession.toString()` 不输出 access/refresh token。
3. 离线皮肤坏索引在写入前保留原始文件；采用不会覆盖既有损坏备份的备份名称，备份失败则停止写入。

### B. 整合包与恢复

1. 整合包事务创建、恢复取得跨进程实例锁后复查持久化游戏标记；预览/prepare 也拒绝运行中实例。
2. 未完成事务按实例名加规范 UUID 精确识别；完整 APPLIED 日志只需清理，不阻止只读预览；缺失/损坏日志保守阻止并交给显式恢复。
3. 整合包清单与恢复清单共用词法范围策略，普通模组的 `mods/` 前缀也不得绕过规范化。
4. 旧的一步更新入口必须拒绝无效旧清单。Prepared 文件及清单内容在应用前重新验证，不能只比较版本号。
5. restore 与 inspect 共享事务恢复、目录交换恢复和 pending 收尾，不能回退旧 active 后再次发布 pending。
6. 升级从 before 快照到 after 快照全程独占实例。现有进程锁是线程绑定 ReentrantLock，文件锁不重入，不能简单在异步链外多套一把锁。实现须显式传递实例操作会话/所有权，保证嵌套事务不重复取锁，异步完成可安全释放，其他用户操作仍获取正常锁。
7. payload、manifest 强制落盘后才发布；发布后验证新点可读且完整，再删除 previous。不能声称 Windows 目录 force 等同完整断电保证。
8. 恢复写入在创建目录前及后重新检查祖先；增加 RESTORING 续做、交换崩溃、无效 pending、真实模组修改的覆盖。
9. 计划有效期仅限制尚未接受的预览；已接受且正在下载/等待第二次确认的计划仍按身份及内容指纹校验，不被旧时间戳误伤。
10. 整合包 files 路径、数量、大小、压缩比、链接条目与 APPLIED 残留预览补直接测试。

### C. 下载、元数据与检查修复

1. 裸 Maven 依赖没有声明摘要时，存在和缺失均不可自动修复；明确报告“缺少声明摘要”，不伪造验证成功。优先不改变持久化 profile 格式、不引入新的摘要抓取请求。
2. 自动修复只能下载声明中有合法可信摘要的条目；UI 复用服务端判定。普通安装与自动修复信任政策分开，不能借全量下载顺便补无摘要条目。
3. 文件发布锁有界、可中断等待；获得后重验目标，正确内容由竞争者完成则直接复用。缺少 size 的 -1 可与同目标同摘要的具体大小合并，两个已知且不同的大小仍拒绝。
4. 日志配置随机临时目标失败/取消时删除其伴随 part/meta；限制日志配置最大 16 MiB（实现选择，待确认）。
5. 修复读写使用同一组注入根目录；不能扫描自定义目录却写 ECLConfig 默认目录。
6. 可选日志配置无效时，检查报告单独诊断 LOGGING 并继续检查其它文件；启动/安装仍拒绝不安全声明，不得简单 catch 后丢弃日志参数（可能丢失 Log4j 安全参数）。不在本轮放宽严格 resolve 的安全契约。
7. 子 Maven 坐标变化不沿用父 artifact。父 classifiers 继承有明确的旧 Forge/LWJGL 兼容测试，当前报告未提供反例，不一律删除；保留该行为并补兼容性依据。
8. 继承信息按原声明保留或删除误导字段，不能向调用方返回虚假的恒 null 契约。
9. hint:local 库校验遵循实际启动路径，不被当作共享库自动写到别处。
10. 旧资源物化前验证对象 SHA-1；修复部分失败也返回 after 报告及失败项；完成标记不在失败前无条件删除。
11. 旧 target.part 采用保留并明确说明不复用的兼容策略，不在没有来源证明时迁移为可续传内容，不自动删除潜在有用断点。

### D. 界面与服务端

1. 启动准备与升级三个阶段对同步提交异常做收尾，PreparedExecution 在未进入任务体时也释放。
2. 升级状态机直接测试选择、两次确认、取消、旧 generation、失败、重试，不只测试反射适配器。
3. 存档备份管理显式绑定正在查看的实例并在弹窗生命周期内固定目标，不从全局启动选择反查。
4. 停止服务器展示 STOPPED/TIMED_OUT/不可控结果；长时间等待不占用共享页面执行器，更不能因 CallerRunsPolicy 落回 FX 线程。
5. Java 探测、实例上下文读取、获取文件锁、备份列表读取移到后台；晚到回调不能更新已关闭弹窗。
6. 启动设置允许 ESC 关闭；实例删除防双击；移除检查结束的重复模态提示；文案键转换使用 Locale.ROOT。
7. 恢复按钮允许进入检查/收尾，文档改为描述实际行为而非声称仅有恢复点时启用（优先保留中断恢复入口）。

### E. 兼容性、维护与文档

1. Windows 快捷方式采用可明确处理 Unicode 的脚本启动方式，测试中文和空格路径，不仅添加 UTF-8 BOM（cmd 不保证按 BOM 解码）。
2. 未知平台一致地拒绝不支持的下载，不能冒充 Windows 又寻找非 Windows 可执行文件。
3. 用户已选择的可选依赖即使只有 versionId，失败也按解析出的 projectId 判断，不静默降级 warning。
4. 删除无消费者的 versionCategory2 迁移及对应描述，不重排其他设置。
5. 无调用 API 仅在全仓引用核实后删除；下载测试数据使用 TempDir 清理；GUI 用语义/容器断言替代脆弱像素条件。
6. 文档同步账户降级、摘要策略、锁所有权、恢复持久化、断点兼容、备份目标、服务端超时及 reduceMotion 实际效果。
7. Windows 链接防护补无需管理员的目录 junction 夹具；文件 symlink 权限不足仍明确记录跳过，不把 junction 当作已覆盖文件链接。

## 已发现报告中需要纠正的建议

- Windows Path 自身 equals/hashCode 通常已大小写不敏感；需以实际 WindowsPath 回归测试判定，不能假设 Map<Path,...> 一定未去重。
- Gradle implementation 不等同 api，不会自动把 logback 编译 API 暴露给消费者。主代码的 LogDirectoryProperty 继承 Logback 类型，不能直接删掉编译依赖。本轮保留现有 implementation，不为虚假的暴露问题做模块搬迁。
- 父 classifiers 继承是旧 Forge/LWJGL 的既有兼容契约，已有跨坐标版本测试。本轮不按报告建议全部删除。
- 无效 logging 的 fail-closed 不能简单改为忽略，避免去掉安全日志参数；改善检查报告的隔离诊断，不静默放宽启动。
- “捕获账户异常一行即可”和“execute 外层持锁即可”都不足以保证文件保留、可见提示及跨异步线程锁安全。

## 验收

- 每个有效问题有对应测试或明确环境验证步骤；对不成立项保留代码依据。
- 使用隔离数据目录执行全量 `check --rerun-tasks`，记录测试数、失败/跳过、静态检查和覆盖率；不复用报告的历史数字。
- 按实际 GUI 改动生成并查看首页、实例页、存档/备份、服务端快照及必要的三语布局。
- 最终检查 git status、git diff、git diff --check，无真实账号、token、生成构建文件或无关变更。
