# 2026-08-13 工作日志

## 修复:ECL.exe 启动报 "Failed to launch JVM"

### 根因
- 打包产物 `dist/windows/ECL/`(jpackage app-image)双击报 "Failed to launch JVM"。
- 实际是应用内部崩溃:`ecl-core` 的 `HttpUtil` 静态初始化抛 NPE →
  `ExceptionInInitializerError` → JavaFX Application start 失败 → jpackage 启动器统一显示 "Failed to launch JVM"。
- 具体位置:`HttpUtil.proxySelectorFor()` 第 59 行 `List.of(httpsProxy, httpProxy, allProxy)`。
  `List.of` 不允许 null 元素,而 `System.getenv("ALL_PROXY")` 在系统未设置该变量时返回 null → NPE。
- 开发机正常是因为设置了 HTTPS_PROXY/HTTP_PROXY 本地代理;干净环境(无代理变量)必崩。

### 修复
- `ecl-core/src/main/java/com/ecl/util/HttpUtil.java`: `List.of(...)` → `new String[]{...}`(数组容忍 null,循环内已有 null/blank 判断)。
- 新增回归测试 `HttpUtilTest.toleratesNullProxyEnvironmentVariables()`。

### 构建与验证
- JDK 21 位置:`C:\Users\ASUS\.jdks\ms-21.0.10`(Microsoft OpenJDK 21.0.10,与打包 runtime 版本一致)。
- `gradlew` 脚本在 Git Bash 下报 "找不到主类 GradleWrapperMain",改用:
  `"$JDK/bin/java.exe" -cp "gradle/wrapper/gradle-wrapper.jar" org.gradle.wrapper.GradleWrapperMain <task>`
- 打包任务:`packageWindowsApp`(ecl-dist),输出到 `dist/windows/ECL`,JDK 须含 jpackage.exe。
- 验证:清除代理环境变量后启动 `ECL.exe`,12 秒后进程存活、窗口正常弹出,日志无异常堆栈。
- CLI 冒烟:`ECL-CLI.exe --version` 输出 `ECL 1.0.0`。

### 备注
- `dist/ECL-1.0.0-windows-x64-apple-ui.zip` 为 8/11 历史遗留分发包(结构不同),未同步更新。
