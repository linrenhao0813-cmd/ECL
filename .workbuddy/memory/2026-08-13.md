## 修复:ECL.exe 启动报 "Failed to launch JVM"

### 根因
- 打包产物 `dist/windows/ECL/`(jpackage app-image)双击报 "Failed to launch JVM"。
- 实际是应用内部崩溃:`ecl-core` 的 `HttpUtil` 静态初始化抛 NPE →
  `ExceptionInInitializerError` → JavaFX Application start 失败 → jpackage 启动器统一显示 "Failed to launch JVM"。
- 具体位置:`HttpUtil.proxySelectorFor()` 第 59 行 `List.of(httpsProxy, httpProxy, allProxy)`。
  `List.of` 不允许 null 元素,而 `System.getenv("ALL_PROXY")` 在系统未设置该变量时返回 null → NPE。
- 开发机正常是因为设置了 HTTPS_PROXY/HTTP_PROXY 本地代理;干净环境(无代理变量)必崩。

### 修复
- `ecl-core/src/main/java/com/ecl/util/HttpUtil.java`: `List.of(...)` → `new String[]{...}`(数组容忍 null,循环内已有 null/blank 判断)。
- 新增回归测试 `HttpUtilTest.toleratesNullProxyEnvironmentVariables()`。

### 构建与验证
- JDK 21 位置:`C:\Users\ASUS\.jdks\ms-21.0.10`(Microsoft OpenJDK 21.0.10,与打包 runtime 版本一致)。
- `gradlew` 脚本在 Git Bash 下报 "找不到主类 GradleWrapperMain",改用:
  `"$JDK/bin/java.exe" -cp "gradle/wrapper/gradle-wrapper.jar" org.gradle.wrapper.GradleWrapperMain <task>`
- 打包任务:`packageWindowsApp`(ecl-dist),输出到 `dist/windows/ECL`,JDK 须含 jpackage.exe。
- 验证:清除代理环境变量后启动 `ECL.exe`,12 秒后进程存活、窗口正常弹出,日志无异常堆栈。
- CLI 冒烟:`ECL-CLI.exe --version` 输出 `ECL 1.0.0`。

### 备注
- `dist/ECL-1.0.0-windows-x64-apple-ui.zip` 为 8/11 历史遗留分发包(结构不同),未同步更新。
- JavaFX 启动时有无害警告 "Unsupported JavaFX configuration: classes were loaded from 'unnamed module'"(类路径方式加载,不影响运行)。

## 修复:Fabric 启动报 ClassNotFoundException: KnotClient

### 根因(ECL bug)
- ECL 安装 Fabric 只写 profile JSON(来自 meta.fabricmc.net),其 libraries 全部为「只有 name+url 的 Maven 坐标」,无 downloads.artifact 字段。
- ECL 的库解析/下载/classpath 构建只认 downloads.artifact,导致 asm×5、sponge-mixin、fabric-loader 全部被跳过:不下载、不进 classpath。
- 启动时 mainClass `net.fabricmc.loader.impl.launch.knot.KnotClient` 找不到 → CNFE。
- 实测证据:versions/fabric-loader-0.19.3-26.2.json 存在,libraries/net/fabricmc 下无 jar。

### 修复内容
- 新增 `com.ecl.game.MavenCoordinates`:坐标 → maven 路径/URL 转换(group:artifact:version → path/url)。
- `Library.parse`:无 downloads 但有 name+url 的库,解析出 artifact(CLI/LaunchCommandBuilder 路径)。
- `GameLauncher.buildClassPath`:同样支持(GUI 路径)。
- `GameDownloader.downloadLibraries` + `getMissingLibraries`、`DownloadLibrariesTask.execute` + `missingLibraryNames`、`VersionManager.areLibrariesReady`:下载与缺失检测支持 maven 坐标库。
- 新增测试:MavenCoordinatesTest、LibraryTest、LaunchCommandBuilderTest 的 fabric 场景(含缺失库 MISSING_FILES)。全部通过。

### 验证
- `ECL-CLI.exe launch fabric-loader-0.19.3-26.2 --dry-run`:classpath 含 fabric-loader/sponge-mixin/asm,mainClass=KnotClient,client jar=versions/26.2/26.2.jar ✅
- 已手动把 7 个 jar 下载到 %APPDATA%\.ecl\libraries\ 对应 maven 路径(用户机器可立即启动)。

### 备注
- GUI 启动路径=GameLauncher(直接操作 JSON);CLI 启动路径=LaunchCommandBuilder(VersionMetadata)。两条都要支持。
- `GameLauncher.java:509`(extractNatives 的 `!lib.has("downloads") continue`)是正确的,勿改。
- Fabric profile 的库无 sha1,下载不校验;如需校验可后续加 .sha1 拉取。

### 问题 2:MavenCoordinates 路径穿越(高风险)
- 现象:原正则 `^([^:]+):([^:]+):([^:]+)$` 允许 `/`、`\`、`..`,拼接 path 后写入 libraries 目录可越界。
- 修复:
  - `MavenCoordinates` 正则收紧:每段首字符字母数字,仅允许 `[A-Za-z0-9._+\-]`,拒绝路径分隔符与 `.`/`..` 段。
  - `FileUtil` 新增 `safeResolveUnder(root, relativePath)`:规范化后校验仍在 root 内,越界抛 IOException;反斜杠先归一化。
  - 应用到所有 libraries 路径点:`GameDownloader.addDownloadIfNeeded`/`getMissingLibraries`、`DownloadLibrariesTask.addIfNeeded`/`missingLibraryNames`、`VersionManager.isArtifactReady`/`areLibrariesReady`、`LaunchCommandBuilder.buildClassPath`、`GameLauncher.buildClassPath`。
