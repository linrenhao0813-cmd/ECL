## HMCL 版本与加载器隔离机制分析
- 任务：分析 HMCL 源码中不同 MC 版本与模组加载器的隔离实现，输出技术方案。
- 获取源码：浅克隆 HMCL-dev/HMCL 到 `E:\ECL\.workbuddy\tmp\HMCL-src`（2026 最新主干，新式 GameInstanceManifest/patches 实例模型）。
- 核心结论：
  - 隔离原则："一实例=一版本目录"，隔离与否 = `getRunDirectory(id)` 一次决策（mods/saves/config 跟随运行目录）。
  - 新式加载器安装不再用 inheritsFrom，而是把加载器封装成 `GameInstancePatch`（id/version/priority）内嵌进实例 json；`DefaultGameRepository.Status.resolve` 合并继承链后按 priority 应用补丁，产出 launchManifest + standaloneManifest 双视图。
  - 默认隔离策略 `DefaultIsolationType`（ALWAYS/MODDED/NEVER，默认 MODDED），判定靠 `LibraryAnalyzer.isModded`（mainClass 前缀）。
  - 隔离落点：实例级设置 `.hmcl/config/instance-game-settings.json` 的 overrideProperties 含 PROPERTY_RUNNING_DIRECTORY → 运行目录=实例根。
  - 启动：`--gameDir`/cwd 解析为 `repository.getRunDirectory(manifest.id())`（DefaultLauncher:534）。
  - 加载器安装：Fabric/Quilt/LiteLoader 走 JSON profile→patch；Forge/NeoForge 走 installer.jar 解包库→patch。
  - 版本 id 命名：UI 层 `InstallersPage.setTxtNameWithLoaders()` = 游戏版本 + "-" + 加载器名（不含加载器版本）。
- 交付：`E:\ECL\docs\HMCL版本与加载器隔离机制分析.md`（设计思路/数据结构/流程/局限性/对照 ECL 落地建议）。
- 对照 ECL：ECL 当前 InstanceIsolation 三态（GLOBAL_SHARED/VERSION_ISOLATED/CUSTOM）≈ HMCL 经典模型；建议补齐实例级运行目录覆盖、MODDED 默认策略、LibraryAnalyzer 式加载器识别。
